# work-log · 工作任务 & 客户上线记录

单文件网页工具，零依赖。三个页面：

- **工作任务**：记录每天的工作任务
- **客户上线**：记录云跨行上线、他行直联上线情况（企业、银行、直联模式、上线日期、城市、实施人员、客户经理），支持 **Excel 导入历史数据**
- **知识库**：沉淀「云跨行FAQ」和「ERP对接」两类知识条目（标题、内容、备注），支持详情查看和全文搜索

数据可同步到 GitHub 私有仓库（`data/tasks.json` / `data/golive.json` / `data/kb.json`），跨设备可用。

## 线上地址

**https://xijun-worklog.netlify.app**（Netlify 托管，部署的是 `site/index.html`，纯页面不含数据）

- 数据不放线上：客户数据只存在浏览器 localStorage + GitHub 私有仓库
- 新浏览器/新电脑首次使用：打开网址 → 设置里填 GitHub token（一次）→ 点「从 GitHub 拉取」
- 日常：数据有变动后点「保存到 GitHub」
- 更新代码：把最新 index.html 拷到 `site/` 目录，然后 `netlify deploy --dir .` + `restoreSiteDeploy` 转正（`--prod` 会 Forbidden）

## 字段

| 字段 | 说明 |
|---|---|
| 序号 | 自动递增，删除不重排 |
| 任务提出日期 | 默认今天 |
| 任务类型 | 他行直联测试 / 生产问题 / 业务需求 / 云跨行上线 / 他行直联上线（支持自定义） |
| 客户名称 | 双击行内编辑；表单里可从常用客户列表联想选择 |
| 任务描述 | 双击表格单元格可直接行内编辑 |
| 问题原因 | 双击行内编辑 |
| 解决方案 | 双击行内编辑 |
| 解决日期 | 完成后填写；状态选「已完成」但留空时自动补当天 |
| 任务状态 | 未解决 / 已完成；双击表格状态格直接切换，未解决的整行黄色高亮 |
| 处理人 | 双击行内编辑；表单里可联想选择，录过的人名自动进列表 |
| 备注 | 双击行内编辑 |

## 功能

- 新增 / 编辑 / 删除任务（全字段）
- 「详情」按钮：弹窗查看该任务全部字段内容，截图可点开大图
- 「链路」按钮：任务链路时间线，按时间记录**进展 / 卡点**；最新一条是卡点时描述列显示红色 🚧 标记，统计栏汇总「卡点中」数量；新卡点自动把上一条未解除的卡点标记为已解除
- 任务描述 / 问题原因 / 解决方案 支持上传截图和文件：截图自动压缩（长边 1200px），随数据一起同步到 GitHub；非图片文件单个 ≤600KB
- 双击「任务描述、问题原因、解决方案、备注」单元格快速行内编辑；双击「状态」格切换已完成/未解决
- 五维筛选：任务类型 / 任务状态 / 客户名称 / 处理人 / 提出日期，另有重置筛选按钮和关键词搜索
- 「显示列」自定义：勾选表格要展示的字段（序号、操作固定显示），选择保存在浏览器本地
- 导出 CSV（Excel 可直接打开）、JSON 备份 / 导入
- GitHub 同步：数据存 `data/tasks.json`，每次修改可在远端留痕（相当于免费版本历史）

### 客户上线

- **行排序**：拖动任意行（拖 ⠿ 手柄）或用操作列 ↑ / ↓ 按钮调整顺序；「⇅ 按日期排序」可按上线日期批量重排
- 序号随行位置自动重排，拖动后的顺序会一起保存并同步到 GitHub；筛选状态下列顺序会看不准，需先「重置筛选」
- 七维筛选：企业名称 / 银行名称 / 直联模式 / 上线日期 / 城市 / 实施人员 / 客户经理
- 📥 导入 Excel 历史数据：表头自动识别（「接入时间／接入日期」也会识别为上线日期），重复记录只补充缺失字段，不产生重复

## 使用方式

### 方式一：本地打开（推荐，数据最安全）
直接双击 `index.html` 用浏览器打开即可。数据存在浏览器 localStorage。

### 方式二：GitHub 同步（跨设备）
1. 在 GitHub 创建**私有**仓库（记录含客户信息，务必私有）
2. 生成 Fine-grained Personal Access Token：Settings → Developer settings → Fine-grained tokens → 只勾选该仓库的 **Contents: Read and write**
3. 打开页面 → ⚙ 设置 → 填入 `owner/repo`、分支 `main`、路径 `data/tasks.json`、Token
4. 「从 GitHub 拉取」合并远端数据；「保存到 GitHub」把当前数据提交到仓库

## 部署到 GitHub Pages（可选）

页面本身不含数据，公开部署也不泄露记录（数据在私有仓库 / 本地）：
1. 仓库 Settings → Pages → Source 选 `main` 分支根目录
2. 访问 `https://<用户名>.github.io/work-log/`

> 注意：若在 Pages 上使用 GitHub 同步，Token 输入在谁浏览器里就存谁浏览器，多人使用各自填各自的 Token。
